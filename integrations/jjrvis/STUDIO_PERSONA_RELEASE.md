# Saved Studio personality in JJRVIS

JJRVIS previously used separate hard-coded character prompts, so choosing a persona in Studio did not choose it for JJRVIS. The authenticated Voice & AI settings now offer separate **Persona**, **Voice** and **Answer model** choices. The selected saved Studio style is used for ordinary conversation, follow-ups, selected-document answers, grounded workspace replies and news briefings. Generated replies show their selected character and actual model; touched local greetings, identity, speech checks, voice help and source summaries are labelled as local utilities.

The broker saves only the chosen UUID in its private runtime preference. It opens Studio’s local SQLite database read-only, reads one bounded style snapshot per reply and returns only record metadata from preference routes. It never writes or copies the persona database. A missing or invalid selected record is visibly unavailable and cannot silently select another saved character. Old clients that omit persona_id preserve the binding; an explicit null selects the built-in character. Saving a character does not copy its stored model into the answer-model preference, change the voice, grant permissions, execute external actions or remove evidence checks.

Its UUID is bound privately; the existing uncensored-3b:latest answer model and British bf_emma voice remain unchanged. The verification JSON records the UUID, name and prompt hash, never the prompt. Unsaved Studio browser drafts and Open WebUI personas are outside this binding; save the record in Studio before selecting it here.
